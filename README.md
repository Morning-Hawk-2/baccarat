# baccarat

バカラディーラー研修シミュレーター

## 目的

バカラ未経験の新人ディーラー研修生（カジノ等の登用・新人研修）向けに、ディーラー業務の一連の流れを仮想テーブルで体験しながら学べるトレーニングツール。

## コンセプト

- **対象ユーザー**: バカラ未経験の研修中ディーラー
- **形式**: ブラウザ完結の実務シミュレーション（仮想テーブルで一連の流れを体験）
- **ハンドの扱い**: 1ハンド完結・毎回独立（シューやバーンカードの管理は行わず、カードは毎回新しく供給）

## トレーニングフロー

各ハンドで以下の流れを体験する。

1. ベット受付（自動演出）
2. カード配布（自動演出）
3. 第三カードルールの判定（**要回答**）
4. 勝敗判定（**要回答**）
5. 配当計算（**要回答**）
6. 支払い（自動演出）

研修生（ディーラー役）が実際に操作・回答するのは**3・4・5の判断・計算ステップのみ**（ボタン/入力で回答）。ベット受付・カード配布・支払いはシステムが自動で進行し、研修生は結果を見るだけ。

各ハンドでは、Player / Banker / Tie / Player Pair / Banker Pair の5種のうち**1種類のベットのみ**が仮想の客によってランダムに置かれる（ベット種別の選ばれ方は「対応ベット」節を参照）。ベット額もハンドごとにランダムに決まる（$5, $10, $25, $50, $100, $500 など実在のチップ単位からランダム選択、範囲は$5〜$500）。第三カードルールの判定（3）・勝敗判定（4）はベット種別によらず毎ハンド共通で行い、配当計算（5）はそのハンドで実際に置かれたベットに対してのみ行う。

研修生の回答が誤っていた場合でも、実際に配られるカード・最終的な勝敗はシステムが**常に正しいバカラルールに従って進行**する。研修生の回答はあくまで採点のみに使われ、シミュレーション自体は分岐しない。

### 3. 第三カードルールの判定

Player → Banker の順に、それぞれ個別に Draw / Stand を回答させる。ナチュラル（初手2枚が8または9）で引きが発生し得ないケースでも省略せず回答させる（正解は常にStand）。

1. Player の初手2枚を提示 → Player の Draw / Stand を回答
2. Banker の初手2枚（および必要に応じて Player の3枚目）を提示 → Banker の Draw / Stand を回答

回答中は、画面上のトグルで第三カードルール表（カンニングシート）を参照できる。

## 対応ベット

- 基本3種: Player / Banker / Tie
- サイドベット: Player Pair / Banker Pair

Perfect Pair・Big/Small など上記以外のサイドベットは v1 のスコープ外。

各ハンドのベット種別選択は、主要3種（Player/Banker/Tie）を優先し、Pair系（Player Pair/Banker Pair）は低頻度で出現するよう重み付けする（実際のカジノでのベット分布感に近づける）。出現確率は Player 40% / Banker 40% / Tie 10% / Player Pair 5% / Banker Pair 5% とする。

## 配当計算ルール

研修生が「配当計算」ステップで回答する数値は**勝ち分（配当金）のみ**を指す（元本は含まない）。負け・プッシュの場合はいずれも0が正解となる。回答は選択式（複数の数値候補から選ぶ）。

| ベット | 配当 | 備考 |
|---|---|---|
| Player | 1倍 | |
| Banker | 1倍 | 5%コミッションはシステムが自動計算（研修生には計算させない） |
| Tie | 8倍 | Tie成立時、Player/Bankerベットはプッシュ（返却）扱い |
| Player Pair | 11倍 | 初手2枚が同ランクで成立 |
| Banker Pair | 11倍 | 初手2枚が同ランクで成立 |

研修生が回答するのは「配当がいくらになるか」の計算結果のみで、コミッションの控除処理自体はシステムが自動で行う。

回答は4択（正解1＋ダミー3）とし、ダミー候補はベット種別ごとに典型的な誤り（例: コミッション控除の誤り、倍率の勘違い、負け/プッシュ時に0を選べないなど）を固定パターンで用意する。

## カード生成

- シューやバーンカードの管理は行わず、毎ハンド新しくカードを供給する（既定方針）
- 第三カードが発生するケース（Player/Banker いずれかが3枚目を引く手）を意図的に増やす重み付け抽選を行い、約70〜80%のハンドで第三カードが発生するようにする（自然なバカラでは約48%）
- 実現方法: 通常の52枚デッキ相当からランダムに配り、目標確率（70〜80%）に合うまで再抽選するリジェクトサンプリング方式とする。カード自体の分布（スート・ランクとも均等）は歪めない
- ナチュラル（引きなしで成立する手）の発生頻度には下限を設けない。第三カード発生率70〜80%の達成を優先する
- カードはランク+スートで表示する（例: K♠, 7♥）。バカラのルール上スートは判定に無関係だが、実務感を出すため表示する

## フィードバック・スコア

- 各回答の直後に正解/不正解を即時表示。不正解の場合は正解値と、判断根拠（適用したルールの条件）を一行添えて表示する
- 正答率は**回答項目単位**（Player Draw/Stand、Banker Draw/Stand、勝敗判定、配当計算をそれぞれ1項目としてカウント）で集計
- セッション中の正答数・正答率をその場で累積表示（保存はしない、ページを離れたらリセット）。項目別（Player Draw/Stand、Banker Draw/Stand、勝敗判定、配当計算）の内訳と全体合計の両方を表示する。手動でその場でリセットできるボタンも用意する（誤クリック防止のため確認ダイアログを表示する）
- 1ハンドの支払いが終わったら、「次のハンドへ」ボタンを研修生が手動でクリックして次のハンドに進む（自動進行はしない）

## スコープ外（v1では扱わない）

- ログイン・ユーザー管理・成績の保存や研修担当者向けの閲覧機能（バックエンドなし）
- シュー残数・リシャッフルタイミングなどの複数デッキ管理
- チップのドラッグ&ドロップ操作やカード配布操作そのものの練習
- リッチなカジノテーブル風ビジュアル（カードは文字/数字中心のシンプル表示、アニメーションは最小限）
- Player Pair / Banker Pair 以外のサイドベット（Perfect Pair、Big/Small など）
- 日本語以外のUI言語対応（多言語化）

## 技術スタック

- React + TypeScript
- Vite（ビルドツール）
- ブラウザ完結（バックエンドなし、静的ホスティング可能）
- デプロイ: GitHub Pages（GitHub Actions によるビルド・デプロイを想定、`https://<user>.github.io/baccarat/` のリポジトリ名サブパスで公開。カスタムドメインは使用しない）
- UI言語: 日本語のみ（v1）
- テスト: ルール判定・配当計算ロジックは Vitest 等による単体テストを必須とする（E2Eはv1では扱わない）。アクセシビリティは自動テストを追加せず手動確認とする
- 画面構成: 単一画面（ページ遷移なし、仮想テーブルと累積成績を常時同一画面に表示）
- レイアウト: モバイル幅を含む完全レスポンシブ対応
- スタイリング: CSS Modules
- 配色: バカラテーブルを連想させるグリーン基調＋シンプルなカードデザイン（リッチなカジノ演出はしない）
- アクセシビリティ: WCAG AA相当を目指す（キーボード操作・ARIA属性・色コントラストに配慮）
